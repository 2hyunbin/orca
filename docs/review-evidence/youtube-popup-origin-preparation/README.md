## Origin behavior

The baseline source initialized both trust surfaces from the requested URL. In the origin-bar presenter it also reused that value after bar/page load completion, allowing a live initial blank document to carry the requested origin before any commit. This baseline is source evidence; no baseline screenshot was captured.

Both presenters now start at `about:blank`, read `mainFrame.url` for attachment, and advance on confirmed main-frame navigation. Electron 43.7.8 implements this getter with `RenderFrameHost::GetLastCommittedURL()` ([versioned Electron source](https://github.com/electron/electron/blob/v43.7.8/shell/browser/api/electron_api_web_frame_main.cc#L459)). The committed security origin is checked as well: a network-shaped URL with an opaque frame origin uses the existing `unknown`/insecure fallback. Failed-load signals read that committed frame state, rather than trusting the failed destination argument. Load completion only redraws the retained state. The existing origin formatter is reused by both presenters; paths, queries and credentials never enter the trust label.

## Real replacement-tab materialization harness

`browser-link-materialization.electron.test.ts` bundles the production preload `onOpenLinkInOrcaTab` subscription, `registerBrowserStateIpcBridge`, full Zustand store and real `BrowserPagePane`. The fixture holds the actual received IPC callback before the renderer bridge consumes it; fixture controls then mutate source state and release that callback. Tab creation and selection use the real store actions, and the production guest lifecycle creates/navigates the `<webview>`; the fixture never directly loads a destination WebContents. Only peripheral app APIs are stubbed, and guest registration checks that the actual contents belong to the host renderer.

Six passing cases establish current behavior:

- Foreground and background controls create exactly one replacement tab, preserve the captured isolated profile/partition, use the isolated Electron session and synthetic cookie, commit the exact destination URL, and select the actual expected browser/unified tab. Background retains the source selection; foreground selects the replacement.
- Removing the source page while the IPC callback is held rejects consumption with no replacement, guest or destination request.
- **Unsafe baseline:** removing the source tab while retaining its page creates a replacement using the other/default profile and cookie.
- **Unsafe baseline:** switching the source profile before consumption creates the replacement under the new profile/session rather than retaining the original authority.
- **Unsafe baseline:** deleting the source profile still creates/navigates a replacement in its retained partition.

These last three tests deliberately assert observed baseline defects and are named accordingly. Two `it.todo` cases explicitly quarantine the future rejection/claim-fence contract; the existing profile unit now uses `it.fails` to express the desired missing-tab rejection. This preparation changes no production tab behavior and does not pretend the unsafe cases are repaired.

The harness starts at synthetic main dispatch, so it does **not** prove real modifier-click association, main-owned document/registration validation, first-navigation fencing, provisional-child discard, route retention, or admission/budget behavior. It uses a folder-shaped workspace with no repository record. Full folder/git/SSH execution coverage, same-ID replacement, profile away-and-back, async validation transitions, retirement/re-registration, and source/root document changes remain part of the dependent repair.
