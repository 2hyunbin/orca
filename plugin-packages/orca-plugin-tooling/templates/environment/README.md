# Company environment provider

Maintain this as a repository named `orca-environments-<company>` under your company’s publisher ID. Commit the prebuilt `dist/provider.mjs`; installing, previewing and approving the package never builds or executes it. Orca runs the reviewed bundle on the selected control host using its verified Node runtime. This is code with your account’s privileges, so review source updates. Data-only language packs cannot declare this provider.

The included adapter forwards protocol-2 lifecycle requests to `POST <base>/operations` and correlated receipt queries to `POST <base>/receipts`. Implement that API in your company gateway, or replace `src/provider-client.mjs` with your own SDK adapter. Preserve explicit account selection, request/operation IDs, expected revisions and receipt correlation. Create/list/sleep/wake/archive/delete apply to provider resources, separately from forgetting an Orca host or workspace. Missing rows and lost contact do not establish deletion.

Configure `ORCA_ENVIRONMENT_PROVIDER_URL` and `ORCA_ENVIRONMENT_PROVIDER_TOKEN` in the control host’s launch environment. The URL must use HTTPS. Credentials belong to that host, never to this repository, recipe, catalog or screenshots. Requests without configuration return authentication-required and make no network call. Redirects are refused; requests/responses are bounded. The adapter never retries a mutation. Your backend must select and verify the requested `contextId` before mutation and persist idempotent receipts before acknowledging it.

For receipt matching, persist the original operation ID, account and the SHA-256 hex digest of the exact UTF-8 operations request body followed by one newline. Do not reserialize or reorder its fields before hashing. Receipt requests contain that digest in `operation.requestDigest`; confirm it against the saved operation and return the separately correlated query identity. An unknown digest must not trigger the original action again.

Run `npm ci --ignore-scripts`, `npm run build`, `npm test` and `npm run validate` when authoring. Then commit the reviewed source, prebuilt bundle and tooling snapshot, version/tag the release and use `.orca-tooling/src/cli.mjs catalog export` with its exact source/ref/license. Contributor CI runs the vendored validator without release credentials. Update vendored tooling in a separate reviewed contribution. Build dependencies are not installed on users’ machines; bundle dependencies into this single ESM file. Use Node built-ins and do not rely on relative imports or native add-ons at execution time. Arguments are literal; request data arrives on standard input.

Publishing a package does not approve it or connect a machine. Orca separately reviews provider commands, account, current inventory, SSH credentials/host keys and changed saved endpoints. Interrupted changes remain unresolved until the backend returns an authoritative matching receipt. A healthy long-lived devbox and an ephemeral sandbox should remain independently identifiable; do not reuse a deleted resource’s ID for a different machine.
